# Author-created Samsung challenge interface

These are independent author-created tests inferred from the delivered kit, not Samsung official or secret cases. This directory contains test data and oracles only. Never import it from `participant/`.

`generate.py` produces JSONL objects. Each object has `id`, `family`, `mode`, `partition`, `factors`, `tools`, `steps`, `replies`, `injected_plans`, `oracle`, and `requirements`. Only `tools` and each step's `event` are delivered to the agent. No case IDs, expected rows, factors, oracle, reference trace, media annotations, or acquisition recipes are model context.

- `mode`: `controller_injected`, `e2e_text`, `e2e_audio`, or `e2e_visual`. Injection results prove controller behavior, not semantic understanding.
- `steps`: `{label, at_ms, event}` in delivery order. `event` uses the kit's `timestamp_ms`, `event_type`, `payload`. A `tool_manifest` is synthesized from `tools` at zero. `scenario_end` is explicit. Malformed-input families deliberately contain invalid events; pass them through without repairing them.
- `replies`: `{api_name, call_index, delay_ms, ignore_cancel, deliveries}`. `call_index` is zero-based per API. Deliveries have `offset_ms` and the raw nested `result`; optional `api_name_override` or `call_id_override` tests identity mismatches. An empty deliveries list means an unknown/lost outcome. Extra unconfigured calls receive an error, never an invented success. A reply is delivered relative to the actual observed call. Record both `tool_completed` and its delivered `tool_result` event, including duplicate/late deliveries. `ignore_cancel` deliberately simulates an uncancellable backend; it does not imply that cancellation undoes effects.
- `injected_plans`: `{trigger, delay_ms, resist_cancel, decision}`. A trigger contains `after_step` and optionally `after_result: {api_name, call_index, delivery_index}`. Match the newest applicable driver milestone when `plan(context)` begins; a rule may be consumed once. A matched delayed rule keeps its original decision even after newer milestones; `resist_cancel` lets it return after cancellation to test stale-plan exclusion. No match returns an empty decision. The controller receives a normal async `setup/plan/close` injected planner; the driver controls these milestones, not participant internals.
- A decision may contain `{"$call_id": {"api_name": "...", "call_index": 0}}` at a leaf. The injected planner recursively replaces that leaf with the observed call ID. This is a test-fixture substitution, never an extension to production input. Missing call bindings must fail the adapter, not silently fabricate IDs.
- `requirements`: asset acquisition / file staging / isolation preconditions. Missing requirements are **blocked**, excluded from executed passes and included in authored/blocked denominators. Run real-model cases without `injected_plans`. Do not turn acquisition recipes into text/audio answers.

`oracle.evaluate_case(case, trace)` returns `{passed, checks, failures}`. `trace` is the unchanged kit's flat trace format: `kind=action` plus flattened `api_name/args/call_id` for `tool_call`; other actions retain `payload`; snapshots are top-level. Completions are `kind=tool_completed`; cancellations are `tool_cancelled` or action `cancel_tool`. Events retain `event_type/payload`. Adapters may add `adapter_error`, `agent_exit`, `shutdown`, and `media_access` observations. Missing required telemetry is a failure, never inferred success. Preserve timestamps and original action order. No aggregate official score is substituted for these obligations.

Timing is in milliseconds. Offline execution may use a virtual clock or a documented accelerated scale, but report it as controller logic evidence. Receipt-to-cancel real latency and the official six-second tail require scale-one acceptance. Keep the same actual ordering for equal-time events. An adapter must record early agent exit, actual post-cancellation background-task leaks, and media reads where an oracle asks for them.

The acceptance lane owns the participant execution adapter. This lane tests oracle satisfiability against explicitly synthetic reference traces and rejects broken-agent trace controls. Neither reference traces nor passing oracle self-checks are participant executions.

The holdout is frozen with hashes before production owners receive answer rows. Share family expectations and this contract freely. Restrict holdout rows to test and acceptance lanes until the frozen-candidate first attempt is recorded. This is procedural isolation in a shared filesystem, not a claim of inaccessible or encrypted data.
