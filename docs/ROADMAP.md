# Development roadmap

This is a prioritized work list, not a list of delivered capabilities. Current behavior is tracked in [What works](WHAT_WORKS.md).

## Submission readiness

1. Validate the adapter and execution environment against the organizer's exact Theme 05 kit.
2. Record real spoken interruption sessions covering echo, accents, background noise, delayed responses, and provider failures.
3. Tie the submitted source, tests, phone build, and technical demonstration to the same candidate.
4. Complete the team's required forms, disclosure fields, and presentation in the supplied format.

## Product reliability

- Measure physical microphone-to-playback interruption latency separately from server/controller timings.
- Exercise long conversations, idle recovery, network changes, and battery endurance.
- Complete actual Spotify authorization and playback/repeat verification.
- Preserve useful previous results on refresh failure, with visible age and coverage.
- Improve ambiguity handling using real user test cases while retaining bounded action authority.

## Useful expansion

- Broaden sourced cards only where provider coverage and attribution are reliable.
- Improve composed widgets and retrieval of work deliberately saved by the user.
- Add integrations through explicit permissions and verifiable outcome receipts.
- Explore multilingual interaction after the existing English authorization path is measured and stable.
- Establish production signing, distribution, migration, and support processes before a public app release.

Keep the interruptible-task controller central. Each addition should produce a useful outcome, preserve action boundaries, and have a clear verification path.
