Checked 24 September 2026. The experiment uses the reviewed checkpoint `f45f0b1`, the nine **public** participant-kit scenarios, the kit's `EvaluationHarness` and `score_scenario`, real-time replay, a 4.5-second planning limit and the participant's 3.5-second acoustic limit. It does not use private expectations or modify the submission. Results are local experiments, not a judge score or a guarantee for hidden cases. Advertised time to first token is not a completed, validated THREAD decision.

An earlier three-repeat source run scored 100 median on every case except audio 06 (56.9 median). Its per-run outliers included visual 07 at 47.7 and unseen-tool 09 at 47.7. The [committed score report](benchmarks/gemini-public-2026-09-24-3x.json) preserves all 27 per-case totals, weighting and medians. It does not contain raw event traces, so it cannot by itself prove action causality or factual quality. The earlier two-repeat diagnostic scored 100 in both repeats on public text cases 01–04 and 08; case 09 scored 100 then 76.9; audio 05 scored 60.8 then 100; audio 06 scored 56.9 twice; visual 07 scored 47.7 then 100. Additional local results are in `.runtime/provider-benchmark/` (ignored by Git). A one-off 100 on audio or visual should not be used as evidence of repeatability.

The evaluator accepts the current `submission.yaml`, but its team field is still `LOCAL_DRAFT_TEAM_METADATA_REQUIRED`; replace that metadata before a real submission.

The first Groq call used JSON Object mode and returned HTTP 200 in 594 ms, but its decision failed validation and case 09 scored 47.7. The JSON Schema requests above passed. The first visual request was rejected with HTTP 429 at the account's **200,000 tokens/day** cap (`used=199592`, `requested=4817`, `retry-after=1905` seconds). After that retry interval, the text control passed again, but a visual retry still received 429 (`used=199731`, `requested=5102`, `retry-after=2088` seconds). This indicates a rolling organization quota, not a single full reset at the first retry time. Another visual attempt failed during connection setup before inference. Those recorded 47.7 scores are infrastructure failures, **not** Qwen vision scores. A later visual probe without local image embedding completed with HTTP 200 and scored 56.9, while an embedding-enabled attempt was again rejected at the daily cap (`used=198619`, `requested=4998`, `retry-after=1563` seconds). [Groq's rate-limit documentation](https://console.groq.com/docs/rate-limits) confirms that limits apply to the organization; this shared 200K/day budget currently prevents a fair full-image or nine-case comparison.

I separately sent the four **public** audio clips to Groq's Whisper Large V3 Turbo and Large V3. Both transcribed the unambiguous second turn of case 05 as “I said Boston.” Both produced garbled text for the ambiguous first turn; Turbo misdetected its language as Icelandic. Large V3 recovered “Book a flight to Boston” and the correction's “New York” more literally in case 06, while Turbo also preserved both city names with grammatical errors. Forcing English made Turbo guess “Austin” on the ambiguous clip, so a forced language must not be treated as added certainty. These are four clips, not an end-to-end route score. The adapter still needs to pass uncertainty through the decision contract and complete the full audio cases.

Two Gemini audio tuning checks did not establish an improvement. With `single_call_reads`, audio 05 scored 53.8/100/72.3 and audio 06 scored 100/100/100; the two-case weighted score was 86.1 versus 78.5 for those cases in the official independent-mode run. This is a different three-repeat sample, so it is a follow-up candidate, not a proven gain. Raising the independent acoustic timeout to 4.3 seconds left audio 06's median at 56.9 (56.9/56.9/76.9).

On the newest `197b671` source, a later `single_call_reads` audio-06 replay scored **56.9/56.9/56.9**: two HTTP 503 planning responses and one timeout. The mode remains experimental. Raising the supported planning limit from 4.5 to 5.5 seconds on unseen-tool text 09 yielded three 47.7 scores, all planning timeouts. This was a focused configuration probe, not a new official full-batch score. A separate full evaluation initially omitted the required media root and scored 71.5; it is excluded. The corrected, frozen 27-attempt run scored **74.1**; see [exact evidence](peer-audits/final-public-evidence.md).

At the integrated `be11e82` source, a correctly configured second full public 9 × 3 evaluation again scored **94.0 weighted**: text and visual medians 100, audio 05 median 100, audio 06 median 56.9. The [new score report](benchmarks/mega-pre-local-asr-2026-09-24-3x.json) is the before measurement for the optional local ASR experiment. A mistaken earlier full invocation omitted `PARTICIPANT_MEDIA_ROOT`; its 82.4 was a missing-media setup error and is excluded from the route comparison. Use `scripts/run_public_eval.ps1` for future full runs so the kit media root is set explicitly.

A minimal in-process switch is the first routing experiment: use the existing Gemini path while healthy, select a validated second provider immediately when a known 429/503 or open circuit is present, and enforce the **whole-turn** deadline locally. Promote a gateway only if an A/B run improves the complete nine-case score and tail latency. This is an inference from the fixed deadline and documented router behavior, not a provider performance claim.

## Paid Gemini decision

Paying for **standard** Gemini raises rate limits but does not demonstrate a faster individual response. [Priority inference](https://ai.google.dev/gemini-api/docs/priority-inference) claims lower latency and higher reliability and currently runs through the Interactions API. Its default Priority limit is 0.3× the Standard limit, and overflow can downgrade to Standard; the response header identifies the tier actually served. For 3.5 Flash-Lite, [published pricing](https://ai.google.dev/gemini-api/docs/pricing) is $0.54 per 1M input tokens and $4.50 per 1M output tokens at Priority, versus $0.30 and $2.50 at paid Standard. The participant uses `generateContent`, so a Priority comparison needs a separate adapter and a small capped paid trial. Billing alone must not be treated as a fix for these 3.5-/4.5-second deadlines. See [rate limits](https://ai.google.dev/gemini-api/docs/rate-limits).

## Decision gate

Run the same frozen participant on one text, one audio and one visual case before spending quota on all nine. If requests complete and the controller accepts the outputs, run all nine public cases three times using the kit's official package evaluator, then a second independent repeat. Compare weighted score, per-case minima, p95 **completed** provider time, invalid output, 429/503, and audio uncertainty. Move a route into the submission only after it matches or improves the incumbent and the complete offline safety suite still passes. Hidden tests remain unknown.

The probe is `scripts/provider_route_probe.py`. It reads local credentials using `--env-file`, redacts prompts and credentials from reports, and has three offline route-boundary checks in `tests/test_provider_route_probe.py`. For example:

```powershell
python scripts/provider_route_probe.py --route groq --env-file 'C:\path\to\.env' --cases pub_09_text_unseen_tool --out '.runtime\provider-benchmark\groq-smoke.json'
python scripts/provider_route_probe.py --route openrouter --env-file 'C:\path\to\.env' --cases pub_09_text_unseen_tool --out '.runtime\provider-benchmark\openrouter-smoke.json'
```
