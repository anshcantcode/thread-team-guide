# Optional faster-whisper in the Samsung judge package

**Assessment date:** 2026-09-24
**Recommendation:** keep faster-whisper as an opt-in desktop feature; **no-go for shipping the pinned large-v3-turbo path to the judge today**. The evidence proves a cached GPU run on one Windows laptop. It does not establish the judge's hardware, platform, package-size allowance, or a CPU performance path.

## What the submission contract supports

The untouched kit accepts a repo or zip containing the kit layout and `submission.yaml`; it supports Python 3.10–3.12. The sample YAML allows a list of extra packages that must resolve from public PyPI. The submission guide permits open models and says to load their weights in `setup()`. See the [official submission instructions](../../theme5_kit/participant-kit/participant-kit/docs/SUBMISSION.md#L5), the [sample YAML](../../theme5_kit/participant-kit/participant-kit/submission.yaml#L1), and its [model and timing guidance](../../theme5_kit/participant-kit/participant-kit/docs/SUBMISSION.md#L30).

The kit's [evaluator](../../theme5_kit/participant-kit/participant-kit/eval_submission.py#L50) parses only a small YAML subset. It requires `team` and `entry_point`, imports and constructs the class, and prints any declared `requirements` as “installed by the portal”; it does not install or verify those packages itself ([validation and requirements reporting](../../theme5_kit/participant-kit/participant-kit/eval_submission.py#L81)). Optional `setup()` has a default **300-second** cap, and each scenario run has a separate **120-second** wall cap. The harness runs setup before the scenario clock; inference remains on the clock ([evaluator caps](../../theme5_kit/participant-kit/participant-kit/eval_submission.py#L124), [run path](../../theme5_kit/participant-kit/participant-kit/eval_submission.py#L171), and [CLI defaults](../../theme5_kit/participant-kit/participant-kit/eval_submission.py#L276)). It creates a fresh agent for every scenario repetition, so loading a model for every agent instance would repeat that cost.

The contract does not specify judge OS, architecture, CPU/RAM, GPU/driver/CUDA, network access, or a submission/model size limit. It also has no documented wheelhouse or wheel-hash field. Those are material unknowns for a native inference engine and a multi-gigabyte checkpoint.

## What is already in THREAD

The existing desktop path is optional and CPU-based: [`requirements-local.txt`](../../requirements-local.txt#L1) allows `faster-whisper>=1.2,<2`; [`requirements-local.lock`](../../requirements-local.lock#L1) currently pins faster-whisper 1.2.1, CTranslate2 4.8.2, PyAV 18.1.0, Hugging Face Hub 1.31.0, tokenizers 0.23.2, and the rest of that environment's dependency graph. [`thread_agent/asr.py`](../../thread_agent/asr.py#L9) lazily imports the recognizer, uses `base.en` with CPU `int8`, and requires local files. [`scripts/setup_speech.py`](../../scripts/setup_speech.py#L1) downloads/warm-loads that model into `.runtime/whisper`. This is a local setup flow, not a model bundle in the Samsung submission.

The pinned [feasibility report](local-whisper-feasibility.md#L1) tested a different model: `dropbox-dash/faster-whisper-large-v3-turbo` at Hugging Face revision `0a363e9161cbc7ed1431c9597a8ceaf0c4f78fcf`. The report records Python 3.11.9, faster-whisper 1.2.1, CTranslate2 4.8.2, CUDA 12.8 and an RTX 4050 Laptop GPU with 6141 MiB. Loading the already cached snapshot took 6.529 seconds; the four warm decodes took 0.402–0.456 seconds each ([measured environment and timings](local-whisper-feasibility.md#L68)). The initial CUDA attempt failed because `cublas64_12.dll` was absent from the process DLL path; the test fixed that by adding the existing Torch library directory to `PATH` ([setup note](local-whisper-feasibility.md#L68)). Torch was present in that benchmark environment, but it is not pinned in `requirements-local.lock`; its presence does not by itself establish that Torch is a required faster-whisper dependency.

At that exact revision the Hub lists a **1.62 GB** repository, including `model.bin`, tokenizer, vocabulary and config files, and marks the checkpoint MIT licensed ([pinned model snapshot](https://huggingface.co/dropbox-dash/faster-whisper-large-v3-turbo/tree/0a363e9161cbc7ed1431c9597a8ceaf0c4f78fcf)). For a reproducible offline package, include the *complete* snapshot, its license/provenance, and SHA-256 hashes for every asset, then load it by local directory with network access disabled. A revision-pinned Hugging Face ID alone still relies on remote availability and first-use download; Hugging Face's [`snapshot_download` revision and offline options](https://huggingface.co/docs/huggingface_hub/package_reference/file_download#huggingface_hubsnapshot_download) make those two modes explicit.

The feasibility result is narrow: on pub05 turn 1 Whisper omitted “Boston” and instead heard “Austin”; the other three clips emitted the target place names. The report itself calls this one warm pass on one GPU a feasibility datapoint, not a stable benchmark, and does not measure CPU inference, streaming/clarification, or end-to-end latency ([results and limits](local-whisper-feasibility.md#L74)).

## Concrete packaging requirements

To ship the pinned large-v3-turbo route reproducibly, all of the following would need to be settled and included:

1. **Freeze the judge target.** Choose an exact Python minor version, OS, architecture and CPU/GPU mode. CTranslate2 publishes desktop wheels for Linux, macOS and Windows on listed architectures and Python 3.9+; GPU execution is documented for Linux/Windows with compatible NVIDIA libraries ([CTranslate2 install matrix](https://opennmt.net/CTranslate2/installation.html)). The kit's Python range alone is not enough to select a wheel.
2. **Freeze the Python artifacts for that target.** Declare faster-whisper 1.2.1 and the exact dependency versions, then produce and record target-compatible wheel hashes (or a target-specific wheelhouse). The local lock is a useful version list, but has no artifact hashes and is not a judge-platform wheelhouse. If using GPU, provision and pin the matching CUDA/cuBLAS/cuDNN runtime and driver contract too; the faster-whisper upstream installation guide documents those GPU libraries and the CPU `int8` option ([upstream requirements and install guide](https://github.com/SYSTRAN/faster-whisper#requirements)). The submission YAML/evaluator currently documents only public-PyPI requirements, so organizer support for an offline wheelhouse must be confirmed.
3. **Supply the model without a setup-time network fetch.** Bundle or mount all files from the 1.62 GB pinned snapshot, verify hashes, and point `WhisperModel` at that local path. Otherwise the first download consumes the 300-second setup cap and depends on judge internet/bandwidth. The 6.529-second result is a cached load on the reported GPU, not a download time or a CPU load time.
4. **Package and initialize it safely.** The current [Samsung package builder](../../scripts/package_samsung_submission.py#L18) has explicit file allowlists for kit files, submission files and participant Python only; it will not include model assets. Its `read_member` reads each member fully into memory ([reader](../../scripts/package_samsung_submission.py#L50)), so simply allowlisting a 1.62 GB model would also require streaming hashing/ZIP writing rather than retaining the entire payload in memory. Keep the recognizer import lazy and reuse one immutable model instance across repeated agents in the evaluator process; otherwise each scenario repetition pays model initialization again. Keep load/warm-up inside `setup()` and inference under the per-scenario wall cap.
5. **Prove the selected route on the judge-equivalent machine.** For the GPU route, require a compatible NVIDIA GPU/runtime; the only observed successful setup was Windows, CUDA 12.8, RTX 4050, about 6 GB reported VRAM. For a CPU-only judge, measure the exact model/quantization and total ASR time on its CPU/RAM under the 120-second scenario cap; the cited feasibility run provides no such evidence. Keep the audio accuracy check separate from speed: four clips include a destination substitution error.

The current Samsung package's `submission.yaml` has no faster-whisper dependency, and the package builder's manifest covers only its explicit runtime files. Consequently the pinned feasibility checkpoint is not part of the judge package today.

## Desktop versus phone

The desktop optional recognizer is `base.en`/CPU `int8` and depends on running `scripts/setup_speech.py` before offline transcription. The large-v3-turbo numbers above are a separate GPU experiment; they do not describe that existing desktop default.

The Android app is another path entirely. Its embedded Python requirements are a pure-Python phone stack, and the Android build uses Chaquopy Python 3.11 plus Android ONNX Runtime 1.23.2 ([phone dependencies](../../android/requirements-phone.txt#L1), [Gradle configuration](../../android/app/build.gradle.kts#L32)). The phone bundles Silero VAD and runs it for local speech detection ([`NeuralVad.kt`](../../android/app/src/main/java/com/thread/app/NeuralVad.kt#L10)); the live relay forwards 16 kHz PCM to Gemini Live ([`live.py`](../../thread_agent/live.py#L440)). Neither `faster-whisper` nor CTranslate2 is in the phone dependency declarations. Do not treat this desktop optional dependency or judge-package proposal as a change to the phone ASR/VAD design.

## Go / no-go

- **Desktop optional route: GO** as an explicitly provisioned local feature. Keep its local model setup separate from the submission package.
- **Judge package with pinned large-v3-turbo: NO-GO for now.** The weight can be pinned, but a 1.62 GB asset is outside the current package allowlist, the available report proves only cached GPU use, and the judge's device/platform and package limits are unknown. Reopen this only after the organizer target and asset/wheel delivery method are confirmed, then freeze hashes and pass the 300-second setup and 120-second per-scenario caps on that target. If the judge is CPU-only or has a strict upload cap, evaluate a smaller CPU model as a separate option; do not claim that the current GPU report validates it.

No model, wheel, or package files were downloaded or installed, and no evaluator or inference run was performed for this assessment.
